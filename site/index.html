How it works

Treat a failed build like a small incident. Rules first, so the answer is fast and explainable.

1

Classify

Ordered rules map the log to one of ten failure kinds. The order matters: a code signing error is checked before a generic compiler error.

2

Gather context

Stack frames, file and line, git branch and SHA, and the changed files turn a log into something a person can act on.

3

Resolve an owner

An explicit override, then CODEOWNERS with real glob rules, then a git-history guess. It reports confidence and the evidence, and says unknown when it does not know.

Run it

Swift 6 on macOS 14 or later.

swift run buildwatch analyze fixtures/xcodebuild-test-failure.log
swift run buildwatch analyze fixtures/make-linker-error.log \
  --format json
swift run buildwatch analyze build.log --format markdown
buildwatch compare old.json new.json   # exit 1 on regression
swift test

Output can be terminal text, Markdown or JSON, and a wrapper can run make or xcodebuild for you.

What this does not do
  • The Swift tool cannot run in a browser. This page re-runs its rule table only. It does not run the stack trace extractor, git lookup or ownership resolver.
  • Confidence is a fixed number per rule, not a measured accuracy.
  • Rule order is the design. A log that matches two rules gets the earlier one, which is why the page lists every rule that matched.
